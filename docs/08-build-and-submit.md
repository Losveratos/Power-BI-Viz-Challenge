# Build and submit

This entry is authored as a **Power BI Project (PBIP)**: the semantic model is
TMDL text, the report is PBIR JSON. Power BI Desktop opens that format directly
and saves it as a `.pbix`. Everything up to that point is generated by scripts in
this repository.

The honest reason it is built this way: the environment that produced this entry
runs Linux and has no Power BI Desktop, so a binary `.pbix` could not be written
or opened there. PBIP is the format that makes a report authorable as text. The
consequence is that one step — opening the project in Desktop, refreshing, and
saving — has to happen on a Windows machine, and the visual confirmation that
goes with it has not happened yet.

---

## What you need

| Requirement | Detail |
|---|---|
| Power BI Desktop | A current version. PBIP save/open is enabled by default in recent releases; if not, turn on **File → Options and settings → Options → Preview features → Power BI Project (.pbip) save option** and restart. |
| The source CSV | `TMDB_movie_dataset_v11.csv` from the [Kaggle dataset](https://www.kaggle.com/datasets/asaniczka/tmdb-movies-dataset-2023-930k-movies). Roughly 700 MB. A Kaggle account is required to download it. |
| Disk and memory | The model imports about 930,000 rows and expands three bridge tables. Expect a refresh of several minutes and a few GB of RAM. |

## Step 1 — Open the project

Open `src/pbip/MovieSuccess.pbip` in Power BI Desktop.

Desktop reads `MovieSuccess.Report/definition.pbir`, which points at
`../MovieSuccess.SemanticModel` by relative path, so both halves load together.
Keep the folder structure intact — moving either folder on its own breaks the
reference.

The tables will be empty at this point. That is expected: a PBIP stores the model
*definition*, not the data.

## Step 2 — Point `CsvPath` at your copy of the CSV

**Transform data → Manage parameters → `CsvPath`**, and set it to the full path of
your `TMDB_movie_dataset_v11.csv`, for example:

```
C:\Users\<you>\Downloads\TMDB\TMDB_movie_dataset_v11.csv
```

This is the same edit the official contest instructions ask every competitor to
make. The starter file shipped with the path hardcoded to its author's own
Downloads folder; this project turns it into a parameter so it is one field
rather than a hunt through the M code.

## Step 3 — Refresh

**Home → Refresh.** Expect several minutes. When it finishes, sanity-check the
figures against `analysis/out/audit_report.md`:

| Check | Expected |
|---|---:|
| `Movies` row count | 85,394 |
| Films Measured Overall | 7,733 |
| Share Of Source Measurable | 0.8% |
| Median Return | 1.96x |
| Break-even Rate | 41.4% |
| Top 100 Overlap Box Office And Return | 0 |

If `Movies` does not come to 85,394, the CSV is a different snapshot from the one
this analysis was built on. Everything downstream still works, but the figures
written into the report's prose will no longer match the data, and
`analysis/07_validate_pbip.py` will tell you which ones drifted.

## Step 4 — Walk the accessibility list

These are the checks that could not be run without Desktop. They are listed in
full in [`06-accessibility.md`](06-accessibility.md); the short version:

- **View → Accessibility checker** (or the Optimize ribbon, depending on version)
  and clear anything it raises.
- Tab through each page. The Key Takeaway should come first on page 1, then the
  scope figures, then the funnel.
- Confirm no text is clipped. Every page is 1920x1080 at `FitToPage`, so check on
  a 16:9 display at 100%.
- Confirm the 2.5x reference lines render with their labels on page 3's return
  chart and page 4's rating chart. If a label is missing, add it manually —
  the threshold must be visible, not implied.
- Check Windows high-contrast mode.

## Step 5 — Save as `.pbix`

**File → Save as → Power BI file (\*.pbix)**. The contest requires a single
`.pbix`, so save it outside `src/pbip/` to avoid confusing the project folder —
`dist/MovieSuccess.pbix` is a reasonable home. `dist/` is gitignored: the file
will be several hundred MB with the data embedded.

If the file is too large to upload, publish to the Power BI Service and submit a
**Publish to Web** URL instead. The rules accept either.

## Step 6 — Submit

Post to the [Contests gallery](https://community.fabric.microsoft.com/t5/Contests-Gallery/bd-p/pbi_contestsgallery)
with:

- **Image** — a screenshot of page 1. The Key Takeaway must be legible in it.
- **Description** — see the draft in [`11-submission-description.md`](11-submission-description.md).
- **File** — the `.pbix`, or a Publish to Web URL.
- **Tag** — `World Champs BCN`.

## Regenerating everything from scratch

```bash
pip install -r analysis/requirements.txt

python analysis/01_extract_model.py       # pull the model out of the starter .pbix
python analysis/02_data_audit.py          # inclusion funnel, missingness, skew
python analysis/03_metric_exploration.py  # correlations, bands, genres, overlap
python analysis/04_robustness.py          # the five adversarial checks
python analysis/05_build_semantic_model.py # TMDL
python analysis/06_build_report.py        # PBIR
python analysis/07_validate_pbip.py       # gate
```

Scripts 05 and 06 delete and rewrite their output directories, and every
identifier is a deterministic UUID5, so re-running produces byte-identical
output. A `git diff` after a run shows a real change or nothing at all.

Script 01 needs network access to raw.githubusercontent.com. Scripts 02 through
07 are offline.

## Known risks in this handover

Stated plainly, because they are the parts most likely to cost time.

1. **The PBIP has never been opened in Power BI Desktop.** TMDL and PBIR are
   well-specified but strict. The schema versions and property shapes here were
   copied from the official starter file, which is itself in PBIR form and was
   written by Desktop, so the grammar is grounded rather than guessed — but a
   rejected property or a TMDL indentation quirk is possible. If Desktop reports
   an error, it names the file and line; the generators in `analysis/` are the
   place to fix it, not the generated files, so the fix survives a rebuild.
2. **Refresh depends on a Kaggle download.** The build environment could not
   reach Kaggle (blocked by its egress policy), so the M queries have not been
   executed against the real CSV. They are transcribed from the starter file's
   own working queries, and the derived columns added afterwards are plain
   `Table.AddColumn` steps, but the first refresh is the first real test.
3. **The rating bands are drawn in a single accent hue**, not the six-step gold
   ordinal ramp recorded in the design system. Per-category colours in PBIR need
   scope-id selectors that are brittle to author blind; the ordinal meaning is
   carried by the band order and the direct labels instead. Worth applying by
   hand in Desktop if there is time.
4. **Two figures in report prose are static text**, not measures: the rank
   correlations (+0.68 and -0.11) in the page 3 subtitles, and the survivorship
   rates (7.8% and 91.1%) in the page 3 caution panel. They come from
   `analysis/out/`, and `07_validate_pbip.py` cross-checks them against the
   analysis output on every build, but they will not update if the CSV snapshot
   changes.

## Alternative: the bundled-data build (no Kaggle account)

If the Kaggle CSV is out of reach, build the variant whose data ships with it:

```bash
python analysis/01_extract_model.py        # starter .pbix -> work/extract
python analysis/08_export_bundled_data.py  # model tables -> work/bundle/MovieSuccess/Data
python analysis/05_build_semantic_model.py --bundled
# then copy src/pbip/MovieSuccess.pbip and MovieSuccess.Report/ next to the
# bundled MovieSuccess.SemanticModel under work/bundle/MovieSuccess/
```

Open `MovieSuccess.pbip` from that folder, set the single `DataFolder`
parameter to the shipped `Data` folder (default `C:\MovieSuccess\Data`),
refresh, and continue from Step 4 above. The CSVs are the official starter
file's model tables exported 1:1 — see ADR-011 in the decision log for the
provenance reasoning. The expected post-refresh figures are identical to the
canonical build's.
